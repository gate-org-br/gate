Authentication

Gate provides an authentication system that validates user identity and establishes application sessions. It supports multiple authentication sources (database, ldap, and oidc), selected by configuration. After successful authentication, Gate issues and refreshes session tokens based on the configured session policy.

Contents

Gate supports configuring one or more authenticators at the same time. Each authenticator defines one authentication source through *.type and its parameters (database, ldap, or oidc).

One authenticator is always the default. It is used when no authenticator name is provided in the request. In configuration terms, omitting a name is equivalent to using default. The default authenticator is configured under gate.auth.default.*.

If the default authenticator type is not explicitly configured, Gate uses database as the default type. Additional authenticators must be named and configured under gate.auth.<name>.*. At runtime, a named authenticator is selected with ?authenticator=<name>.

Typical usage:

  • Configure default for the primary user base.
  • Add one or more named authenticators for alternative identity providers.
  • Use the request parameter authenticator only when selecting a named authenticator.

You can also scope configuration by app context using <context>.auth.*. 

# Default authenticator (used when "authenticator" is not provided)
"gate.auth.default.type": "database"

# Named authenticator "corp" (selected with ?authenticator=corp)
"gate.auth.corp.type": "oidc"
"gate.auth.corp.oidc.client_id": "gate-corp"
"gate.auth.corp.oidc.provider": "https://idp-corp.example.com/realms/main"
"gate.auth.corp.oidc.redirect_uri": "https://app.example.com/Gate?authenticator=corp"

# Named authenticator "partners" (selected with ?authenticator=partners)
"gate.auth.partners.type": "ldap"
"gate.auth.partners.ldap.server": "ldaps://ldap-partners.example.com:636"

If a request references an unknown authenticator name, authentication setup fails. Keep authenticator names stable and consistent between frontend links and backend configuration.

Database

Use database for local username/password authentication against Gate user storage.

Parameter Required Default Description Example
*.type Yes - Sets the authenticator type. "gate.auth.default.type": "database"
LDAP

Use ldap to authenticate users against an LDAP directory.

Parameter Required Default Description Example
*.type Yes - Sets the authenticator type. "gate.auth.default.type": "ldap"
*.ldap.server Yes - LDAP server URL, including protocol and port. "gate.auth.default.ldap.server": "ldaps://ldap.example.com:636"
*.ldap.security_protocol No null Optional LDAP security protocol (for example, SSL). "gate.auth.default.ldap.security_protocol": "ssl"
*.ldap.client_username No null Technical account used for LDAP search/bind before validating user credentials. "gate.auth.default.ldap.client_username": "cn=svc,dc=example,dc=com"
*.ldap.client_password No null Password for the LDAP technical account. "gate.auth.default.ldap.client_password": "<password>"
*.ldap.root_context No "" Base DN used during LDAP searches. "gate.auth.default.ldap.root_context": "dc=example,dc=com"
*.ldap.database_fallback No false When true, falls back to database password validation if LDAP lookup does not find the user. "gate.auth.default.ldap.database_fallback": "true"
OIDC

Use oidc to authenticate with an OpenID Connect provider.

Parameter Required Default Description Example
*.type Yes - Sets the authenticator type. "gate.auth.default.type": "oidc"
*.oidc.client_id Yes - OIDC client identifier registered in the identity provider. "gate.auth.default.oidc.client_id": "gate-client"
*.oidc.provider Yes - Provider base URL used to discover OIDC endpoints. "gate.auth.default.oidc.provider": "https://idp.example.com/realms/main"
*.oidc.redirect_uri Yes - Application callback URL registered in the provider. "gate.auth.default.oidc.redirect_uri": "https://app.example.com/Gate"
*.oidc.client_secret No null Client secret used for confidential clients. "gate.auth.default.oidc.client_secret": "<secret>"
*.oidc.scope No openid email profile Scopes requested during authentication. "gate.auth.default.oidc.scope": "openid email profile"
*.oidc.user_id No email Claim/field used to map provider identity to the Gate user. "gate.auth.default.oidc.user_id": "email"
*.oidc.logout_uri No null Provider logout endpoint used for federated sign-out. "gate.auth.default.oidc.logout_uri": "https://idp.example.com/logout"
*.oidc.configuration_endpoint No <provider>/.well-known/openid-configuration Custom discovery endpoint URL. "gate.auth.default.oidc.configuration_endpoint": "https://idp.example.com/.well-known/openid-configuration"
*.oidc.authorization_endpoint No From discovery Custom authorization endpoint override. "gate.auth.default.oidc.authorization_endpoint": "https://idp.example.com/protocol/openid-connect/auth"
*.oidc.token_endpoint No From discovery Custom token endpoint override. "gate.auth.default.oidc.token_endpoint": "https://idp.example.com/protocol/openid-connect/token"
*.oidc.userinfo_endpoint No From discovery Custom userinfo endpoint override. "gate.auth.default.oidc.userinfo_endpoint": "https://idp.example.com/protocol/openid-connect/userinfo"
*.oidc.jwks_uri No From discovery Custom JWKS endpoint override for token signature validation. "gate.auth.default.oidc.jwks_uri": "https://idp.example.com/protocol/openid-connect/certs"

OIDC supports three credential entry points: authorization code flow via code/state, bearer token validation, and resource owner password credentials via HTTP Basic authorization.

For authorization code flow, Gate generates and validates an encrypted/signed state payload containing the PKCE verifier and nonce.

Session Parameters

These parameters are global and apply regardless of authenticator type.

Gate always issues a signed session token. Depending on configuration, the token may also embed the authenticated user data (stateless token) and/or require a backing row in gate.Session for revocation checks (revocable).

Duration format is not milliseconds. Use Gate duration strings: Nd Nh Nm Ns (for example, 1h 30m), HH:MM, or HH:MM:SS. A plain number (for example, 30) is interpreted as minutes.

Parameter Required Default Description Example
gate.auth.session.idle_timeout No 1h Idle session duration used to compute token expiration. "gate.auth.session.idle_timeout": "45m"
gate.auth.session.timeout No 24h Maximum absolute session duration from token issue time. "gate.auth.session.timeout": "10h"
gate.auth.session.stateless-token No false When true, embeds the authenticated user in the token and avoids a user lookup on each request. "gate.auth.session.stateless-token": "true"
gate.auth.session.revocable No false When true, stores a session row in gate.Session and rejects tokens whose session was revoked. "gate.auth.session.revocable": "true"

Session refresh extends the idle expiration while preserving the original issue time, so gate.auth.session.timeout remains the absolute upper bound.

Logout revokes the current session token. When sessions are not revocable, logout still updates user activity and removes the client-side session token, but there is no server-side token blacklist.

Secret Key

Gate uses a single secret key for authentication security. From this secret key, Gate derives:

  • the key used to sign and validate session tokens;
  • the key used to encrypt/sign OIDC state data.

Key source resolution order: gate.key-store.file first, then gate.secret-key-file, then gate.secret-key.

If none of the key parameters is configured, Gate generates a random in-memory key at startup. This is valid behavior, but all active tokens become invalid after application restart.

Parameter Required Default Description Example
gate.secret-key No null Base64 master secret value from configuration/environment. Recommended when injecting secrets via secret manager. "gate.secret-key": "<BASE64_SECRET>"
gate.secret-key-file No null Path to a file containing a Base64 master secret. Used only if gate.key-store.file is not set. "gate.secret-key-file": "/etc/secrets/gate-secret.key"
gate.key-store.file No null Path to JCEKS or PKCS12 keystore used as secret source. Highest priority when present. "gate.key-store.file": "/etc/secrets/gate-keystore.p12"
gate.key-store.secret-key No secret-key Secret key alias inside the keystore. Applies only when gate.key-store.file is configured. "gate.key-store.secret-key": "secret-key"
gate.key-store.password No changeit Keystore password used to load the key. Applies only when gate.key-store.file is configured. "gate.key-store.password": "<password>"

Choose one strategy for predictability in production: keystore, secret file, or inline Base64 secret.

Complete Example

The following application.yaml shows a multi-authenticator setup with: default database auth, OIDC for corporate SSO, LDAP for partners, and global session/key settings. 

# ------------------------------
# Global session policy
# ------------------------------
"gate.auth.session.idle_timeout": "45m"
"gate.auth.session.timeout": "10h"
"gate.auth.session.stateless-token": "false"
"gate.auth.session.revocable": "true"

# ------------------------------
# Secret key strategy (inline Base64)
# ------------------------------
"gate.secret-key": "REPLACE_WITH_BASE64_SECRET_VALUE"

# ------------------------------
# Default authenticator (implicit when no authenticator name is provided)
# ------------------------------
"gate.auth.default.type": "database"

# ------------------------------
# Named authenticator: corporate SSO (OIDC)
# selected with ?authenticator=corp
# ------------------------------
"gate.auth.corp.type": "oidc"
"gate.auth.corp.oidc.client_id": "gate-corp"
"gate.auth.corp.oidc.client_secret": "REPLACE_WITH_CORP_CLIENT_SECRET"
"gate.auth.corp.oidc.provider": "https://idp-corp.example.com/realms/main"
"gate.auth.corp.oidc.redirect_uri": "https://app.example.com/Gate?authenticator=corp"
"gate.auth.corp.oidc.scope": "openid profile email"
"gate.auth.corp.oidc.user_id": "email"
"gate.auth.corp.oidc.logout_uri": "https://idp-corp.example.com/protocol/openid-connect/logout"

# ------------------------------
# Named authenticator: partner directory (LDAP)
# selected with ?authenticator=partners
# ------------------------------
"gate.auth.partners.type": "ldap"
"gate.auth.partners.ldap.server": "ldaps://ldap-partners.example.com:636"
"gate.auth.partners.ldap.security_protocol": "ssl"
"gate.auth.partners.ldap.client_username": "cn=svc_gate,ou=system,dc=partners,dc=example,dc=com"
"gate.auth.partners.ldap.client_password": "REPLACE_WITH_LDAP_SERVICE_PASSWORD"
"gate.auth.partners.ldap.root_context": "dc=partners,dc=example,dc=com"
"gate.auth.partners.ldap.database_fallback": "false"
