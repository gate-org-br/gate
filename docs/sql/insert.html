Insert

Use Insert when you want explicit field mapping and SQL-friendly generated key handling.

Single Insert

This is the most common insert flow.

Insert.into("Organization")
	.set("code", value.getCode())
	.set("name", value.getName())
	.set("host", value.getHost())
	.build()
	.connect(linkSource.get())
	.fetchGeneratedKey(ID.class)
	.ifPresent(value::setId);
Insert Ignore

Use ignore() when duplicate rows are expected and should not fail the flow.


Insert
	.ignore()
	.into("UserAccount")
	.set("id", value.getId())
	.set("taxId", value.getTaxId())
	.set("ContactCenter$id", value.getContactCenter().getId())
	.build()
	.connect(linkSource.get())
	.execute();
Batch Insert

Use from(...) plus method references when inserting many values of the same shape.

Insert.into("Department")
	.from(Department.class)
	.set("name", Department::getName)
	.set("active", Department::getActive)
	.build()
	.connect(linkSource.get())
	.fetchGeneratedKey(values, ID.class, Department::setId);
Property References

When the inserted data comes from a Java model, property references keep the mapping close to the model instead of repeating the same column/value pair by hand. 

Insert.into(User.class)
	.set(User::getName, value.getName())
	.set(User::getUsername, value.getUsername())
	.set(User::getActive, value.getActive())
	.build()
	.connect(linkSource.get())
	.fetchGeneratedKey(ID.class)
	.ifPresent(value::setId);
Property Reference Lists

When the insert should copy several values directly from the same object, use the list-based overload instead of repeating one set(...) per property.

This is useful when the Java object already matches the insert shape and you want the statement to say only which properties participate in the write. 

Insert.into(value)
	.set(List.of(
		User::getName,
		User::getUsername,
		User::getActive))
	.build()
	.connect(linkSource.get())
	.fetchGeneratedKey(ID.class)
	.ifPresent(value::setId);
Conditional Clauses

Use when(...) when a column should only be included if some runtime condition is true.

This is useful in insert flows because many values are optional by nature: attachments, binary payloads, secondary timestamps, derived metadata, or columns that only make sense in a specific branch of the workflow. With when(...), you keep the insert definition linear and simply say that the next assignment belongs to the query only when the condition is satisfied.

After when(...), the API offers supplier-based set(...) overloads. That makes the value lazy. If the condition is false, the assignment is not added and the supplier is never evaluated. This matters not only for performance but also for correctness, because optional values often depend on state that only exists in the active branch.

In practice, this gives you a safe way to keep optional columns close to the base insert instead of splitting the whole statement into several branches. 

Insert.into("Attachment")
	.set("name", file.getName())
	.when(file.getContent() != null).set("content", file::getContent)
	.when(file.getSize() != null).set(Long.class, "size", file::getSize)
	.build()
	.connect(linkSource.get())
	.execute();
Main Methods
Method Use it for
into(...) Choose the target table
set(...) Map a column to a fixed value, extractor, or property reference
set(List.of(...)) Copy several properties from the current object in one step
ignore() Turn the insert into an ignore-style insert when supported by the database
when(...) Conditionally add values; if the condition is false, the next value is skipped
from(...) Describe batch inserts based on an object type
build() Produce the executable insert
fetchGeneratedKey(...) Read one generated key or propagate generated keys into a collection
fetchGeneratedKeys(...) Read multiple generated keys
execute() Run the insert without reading generated keys
