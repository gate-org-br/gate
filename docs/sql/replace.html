Replace

Use Replace when the database supports replace-style writes and your flow wants to overwrite an existing row or insert it when it does not exist yet.

Single Replace

Use it when the write semantics are "insert or replace".

Replace.into("UserPreference")
	.set("User$id", userId)
	.set("theme", value.getTheme())
	.set("language", value.getLanguage())
	.build()
	.connect(linkSource.get())
	.execute();
Property References

For model-based writes, property references help keep the value mapping explicit and aligned with the Java type. 

Replace.into(UserPreference.class)
	.set(UserPreference::getTheme, value.getTheme())
	.set(UserPreference::getLanguage, value.getLanguage())
	.build()
	.connect(linkSource.get())
	.execute();
Property Reference Lists

When several columns should come directly from the same object, the list-based overload keeps the replace statement shorter and clearer.

This is the natural choice when the write is basically "replace this object using these properties" rather than "manually map every column one by one". 

Replace.into(value)
	.set(List.of(
		UserPreference::getTheme,
		UserPreference::getLanguage))
	.build()
	.connect(linkSource.get())
	.execute();
Batch Replace

Use from(...) for replace flows that process many objects of the same shape.

Replace.into("Department")
	.from(Department.class)
	.set("name", Department::getName)
	.set("active", Department::getActive)
	.build()
	.connect(linkSource.get())
	.execute(values);
Conditional Clauses

Use when(...) when a replace value should only be present under a runtime condition.

In replace flows this is especially useful when part of the row is optional. You still define one replace statement, but the columns that only make sense in a given scenario are attached conditionally instead of forcing multiple Java branches around the same operation.

After when(...), the API offers supplier-based set(...) methods. That makes the value lazy: it is only read when the condition is true and the assignment is really included in the final SQL.

This is the right choice whenever the value is optional, derived, or expensive to obtain, because it aligns value evaluation with clause inclusion. 

Replace.into("UserPreference")
	.set("User$id", userId)
	.when(value.getTheme() != null).set("theme", value::getTheme)
	.when(value.getLanguage() != null).set("language", value::getLanguage)
	.build()
	.connect(linkSource.get())
	.execute();
Main Methods
Method Use it for
into(...) Choose the target table or Java type
set(...) Map columns to fixed values, extractors, or property references
set(List.of(...)) Copy several properties from the current object in one step
from(...) Describe batch replace operations from a Java type
when(...) Include a value assignment only when a runtime condition is true
build() Produce the executable replace statement
execute() Run the replace statement
