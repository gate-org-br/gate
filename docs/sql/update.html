Update

Update operations should make scope and safety explicit: clear where predicates, optional assignments with when(...), and row-count guards.

Standard Update

Clear table/field mapping with ID-scoped update.

Update.table("UserAccount")
	.set("taxId", value.getTaxId())
	.set("Role$id", value.getRole().getId())
	.set("ContactCenter$id", value.getContactCenter().getId())
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute();

Why this is useful:

  • Update scope is explicit
  • Low chance of accidental full-table updates
  • Easy to review and maintain
Conditional Assignments with when(...)

Only assign optional fields when values exist.

Update.table("Category")
	.set("name", value.getName())
	.set("description", value.getDescription())
	.when(value.getIcon() != null).set("icon", value.getIcon())
	.where(Condition.of("id").eq(ID.class, value.getId()))
	.build()
	.connect(getLink())
	.execute();

Why this is useful:

  • Prevents unintended null overwrites
  • Keeps optional logic inside the fluent block
  • Matches patch-like update semantics
Not Found Guard

Common production guard: fail if no row was updated.

if (Update.table("Organization")
	.set("name", value.getName())
	.set("host", value.getHost())
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute() == 0)
	throw new NotFoundException();

Why this is useful:

  • No silent no-op write
  • Makes API behavior deterministic
  • Good protection against stale IDs

Batch pattern with entity extractors.
