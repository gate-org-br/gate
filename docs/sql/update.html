Update

Use Update when the write needs to be explicit: which table, which columns, and which rows are affected.

Standard Update

A clear update normally has a fixed where clause.

Update.table("UserAccount")
	.set("taxId", value.getTaxId())
	.set("Role$id", value.getRole().getId())
	.set("ContactCenter$id", value.getContactCenter().getId())
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute();
Optional Assignments

Use when(...) to include a column assignment only when the value exists.

Update.table("Category")
	.set("name", value.getName())
	.set("description", value.getDescription())
	.when(value.getIcon() != null).set("icon", value.getIcon())
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute();
Conditional Clauses

Use when(...) when an assignment should only exist if some runtime condition is true.

This is important in updates because optional assignments are common: patch-style fields, nullable uploads, audit values that only exist in specific transitions, or values that should only be sent when the caller explicitly asked for them. With when(...), the update stays linear and readable while still expressing those optional branches.

After when(...), the fluent API offers Supplier-based set(...) methods. This keeps the value lazy: if the condition is false, the assignment is skipped and the supplier is not evaluated.

The result is a safer update definition. The SQL only receives the columns that belong to the active branch, and the Java code does not waste work computing values for assignments that never enter the statement. 

Update.table("Category")
	.set("name", value.getName())
	.when(value.getIcon() != null).set("icon", value::getIcon)
	.when(value.getUpdatedAt() != null).set(LocalDateTime.class, "updatedAt", value::getUpdatedAt)
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute();
Property References

In update flows based on Java models, property references help keep extractors explicit and avoid repeating column names in the value side. 

Update.table("Ticket")
	.from(Ticket.class)
	.set("notifiedUsers", Ticket::getNotifiedUsers)
	.where(Condition.from(Ticket.class)
		.expression("id").eq(Ticket::getId))

Property Reference Lists

When an update should copy several values from the current object, use the list-based overload instead of repeating each property assignment manually.

This is especially useful in object-based updates where the write shape is already described by the model and the query should only declare which properties are part of the update. 

Update.table(value)
	.set(List.of(
		Category::getName,
		Category::getDescription))
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute();
Not Found Guard

If the API expects an existing row, check the affected row count explicitly. 

if (Update.table("Organization")
	.set("name", value.getName())
	.set("host", value.getHost())
	.where(Condition.of("id").eq(value.getId()))
	.build()
	.connect(getLink())
	.execute() == 0)
	throw new NotFoundException();
Main Methods
Method Use it for
table(...) Choose the table to update
set(...) Assign new values to columns, including values extracted through property references
set(List.of(...)) Copy several properties from the current object in one step
when(...) Include a column assignment only when a runtime condition is true
where(...) Restrict which rows will be updated
build() Produce the executable update
execute() Run the update and return the affected row count
