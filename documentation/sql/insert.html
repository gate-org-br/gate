Insert

In production DAOs, insert flows usually follow this sequence: map fields with set(...), execute through Link, and collect generated IDs.

Single Row + Generated Key

Most common insert pattern.

Insert.into("Organization")
	.set("code", value.getCode())
	.set("name", value.getName())
	.set("host", value.getHost())
	.build()
	.connect(getLink())
	.fetchGeneratedKey(ID.class)
	.ifPresent(value::setId);

Why this is useful:

  • Explicit and readable field mapping
  • Generated ID is attached immediately
  • No manual SQL string formatting
Insert Ignore

Useful for idempotent association or bootstrap flows.

Insert.into("UserAccount")
	.ignore()
	.set("id", value.getId())
	.set("taxId", value.getTaxId())
	.set("ContactCenter$id", value.getContactCenter().getId())
	.build()
	.connect(getLink())
	.fetchGeneratedKey(ID.class)
	.ifPresent(value::setId);

Why this is useful:

  • Safer behavior under uniqueness races
  • Reduces duplicate-key exceptions in controlled cases
  • Still supports generated key capture
Optional Binary/Attachment Insert

Pattern used for nullable files and payloads.

if (value != null && value.getFile() != null)
	Insert.into("Attachment")
		.set("file", value.getFile())
		.build()
		.connect(getLink())
		.fetchGeneratedKeys(ID.class)
		.forEach(value::setId);

Why this is useful:

  • Avoids inserting meaningless empty rows
  • Keeps null handling explicit
  • Works with key-list APIs
Batch/Collection Key Propagation

Use generated key helpers for collections when supported by your flow.

Insert.into("Department")
	.from(Department.class)
	.set("name", Department::getName)
	.set("active", Department::getActive)
	.build()
	.connect(getLink())
	.fetchGeneratedKey(values, ID.class, Department::setId);

Why this is useful:

  • No manual key assignment loops
  • Keeps batch write APIs concise
  • Pairs well with repository-level bulk operations
