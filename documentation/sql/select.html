Select

Select is used from simple projections to multi-join analytical queries. This page prioritizes high-value patterns seen in production DAOs.

Resource SQL + Dynamic Condition

Most common production pattern: SQL in resource file, dynamic predicates in Java.

List<Map<String, Object>> rows = Select
	.of(getClass().getResource("CallReportDao/search(Call).sql"))
	.where(getCondition(call))
	.orderBy("Call.createdAt")
	.build()
	.connect(getLink())
	.fetchMapList(String.class, String.class, LocalDateTime.class);

Why this is useful:

  • Long SQL stays readable in dedicated files
  • Java still controls dynamic filtering
  • Typed fetch output for predictable mapping
Join + isEq

Use isEq for field-to-field join conditions.

List<User> users = Select
	.expression("UserAccount.id").as("id")
	.expression("User.name").as("name")
	.expression("User.username").as("username")
	.from("UserAccount")
	.join("gate.User").on(Condition.of("UserAccount.id").isEq("User.id"))
	.where(Condition.of("UserAccount.ContactCenter$id").eq(contactCenter.getId()))
	.orderBy("User.name")
	.build()
	.connect(getLink())
	.fetchEntityList(User.class);

Generated SQL shape:

select UserAccount.id as "id", User.name as "name", User.username as "username"
from UserAccount
join gate.User on UserAccount.id = User.id
where UserAccount.ContactCenter$id = ?
order by User.name
Conditional Access Join

Pattern used for role-based visibility in list screens.

List<Organization> organizations = Select
	.expression("Organization.id").as("id")
	.expression("Organization.name").as("name")
	.from("Organization")
	.leftJoin("Access")
	.on(Condition.of("Organization.id").isEq("Access.Organization$id")
		.and("Access.User$id").eq(getUser().getId()))
	.where(Condition.TRUE
		.and().when(!getUser().isSuperUser()).expression("Access.id").isNotNull())
	.orderBy("Organization.name")
	.build()
	.connect(getLink())
	.fetchEntityList(Organization.class);

Why this is useful:

  • Single query for super-user and regular-user flows
  • Readable and auditable access rule
  • No post-filter in application memory
Group By and Rollup

Analytical summaries with rollup are common in dashboard DAOs.

DataGrid grid = Select
	.of(getClass().getResource("CallReportDao/byQueue(Call).sql"))
	.where(getCondition(call))
	.groupBy("Queue.id")
	.withRollup()
	.build()
	.connect(getLink())
	.fetchDataGrid(String.class, Integer.class, Integer.class, Integer.class)
	.rollup();

Why this is useful:

  • Aggregations are done in SQL, not in Java loops
  • Natural fit for report pages and BI-like widgets
  • Typed grid output keeps rendering stable
Pagination

Use paginate with typed map pages for server-side listing endpoints.

Page<Map<String, Object>> page = Select
	.of(getClass().getResource("CallReportDao/search(Call, String, int, int).sql"))
	.where(getCondition(call))
	.sort(order)
	.paginate(pageSize, pageIndx)
	.build()
	.connect(getLink())
	.fetchMapPage(pageSize, pageIndx, ID.class, String.class, LocalDateTime.class);

Why this is useful:

  • Consistent page contract for UI/API consumers
  • Avoids loading full result sets
  • Works with dynamic ordering and filters
exists(select ...)

When you need a boolean existence query, use Select.exists(...).

boolean exists = Select.exists(Select
		.expression("id")
		.from("User")
		.where(Condition.of("id").eq(userId)))
	.build()
	.connect(getLink())
	.fetchBoolean();

Generated SQL shape:

select exists (select id from User where id = ?)
